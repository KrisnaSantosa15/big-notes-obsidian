# dicoding.com pushes index deltas; the AI service keys them on module_id

Course material and solved discussion Q&A reach the AI service because dicoding.com POSTs a ZIP on `CourseTutorialWasSetAsPublished` and on a discussion being marked solved. The AI service never pulls. Each push carries only what changed — one module, one discussion — and the AI service upserts it, keyed on `module_id` (courses) or `discussion_id` (discussions), with matching DELETE endpoints for removal.

There is no alternative to pushing: the AI service has no database connection to dicoding.com, no cron, and no puller of any kind. Its indexing endpoints existed and worked but nothing called them, so without this a course's forum answers would hit the `FileNotFoundError` branch on every request. The only precedent for dicoding.com feeding an AI backend is Explain-with-AI's `UpdateAIVectorEmbeddingListener`, which is the shape this follows — with a different cadence: Explain-with-AI batches to a weekly `pushLaterOnce`, because its backend rebuilds whole collections. Ours are cheap single-item upserts, so there is nothing worth collapsing and each trigger pushes immediately.

`module_id` as the merge key was a change made upstream specifically for this, replacing a full-replace build. The alternative — Chester AI's filename matching — is demonstrably broken: it derives the key from slugified course and tutorial names, so editing a tutorial's title writes chunks under a new filename while the old-titled chunks are never matched for deletion and orphan in the collection forever. An integer id survives a title edit. Note the vocabulary collision this creates: "module" is the AI service's name for what Dicoding calls a tutorial, and `module_id` is `developer_journey_tutorials.id` unchanged.

One limit accepted rather than solved: there is no backfill for content published before this ships — deliberate, since the feature is pre-launch, but it needs a one-off command if that stops being true. Verification of each push was initially accepted as a limit too; it is not one any more, see ADR-0011.
